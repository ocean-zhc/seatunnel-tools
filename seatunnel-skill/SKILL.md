# Apache SeaTunnel OpenCode Skill

Apache SeaTunnel is a **multimodal, high-performance, distributed data integration tool** capable of synchronizing vast amounts of data daily. It connects hundreds of evolving data sources with support for real-time, CDC (Change Data Capture), and full database synchronization.

## Quick Start

### Prerequisites

- **Java**: JDK 8 or higher
- **Maven**: 3.6.0 or higher (for building from source)
- **Python**: 3.7+ (optional, for Python API)
- **Git**: For cloning the repository

## Usage

### 1. Job Configuration (HOCON Format)

```hocon
env {
  job.mode = "BATCH"  # or STREAMING
  job.name = "My Job"
  parallelism = 4
}

source {
  SourceConnector {
    option1 = value1
    schema = {
      fields {
        column1 = "type"
      }
    }
  }
}

transform {
  TransformName {
    option = value
  }
}

sink {
  SinkConnector {
    option1 = value1
  }
}
```

### 2. Common Use Cases

#### MySQL to PostgreSQL (Batch)
```hocon
env { job.mode = "BATCH" }
source {
  Jdbc {
    driver = "com.mysql.cj.jdbc.Driver"
    url = "jdbc:mysql://mysql-host:3306/mydb"
    user = "root"
    password = "password"
    query = "SELECT * FROM users"
  }
}
sink {
  Jdbc {
    driver = "org.postgresql.Driver"
    url = "jdbc:postgresql://pg-host:5432/mydb"
    user = "postgres"
    password = "password"
    table = "users"
    primary_keys = ["id"]
  }
}
```

#### Kafka Streaming to Elasticsearch
```hocon
env { job.mode = "STREAMING", parallelism = 2 }
source {
  Kafka {
    bootstrap.servers = "kafka-host:9092"
    topic = "events"
    consumer.group = "seatunnel-group"
    format = "json"
    schema = { fields { event_id = "bigint", event_name = "string", timestamp = "bigint" } }
  }
}
transform {
  Sql { sql = "SELECT event_id, event_name, FROM_UNIXTIME(timestamp/1000) as ts FROM source" }
}
sink {
  Elasticsearch { hosts = ["es-host:9200"], index = "events" }
}
```

#### CDC from MySQL to Kafka
```hocon
env { job.mode = "STREAMING" }
source {
  Mysql {
    server_id = 5400
    hostname = "mysql-host"
    port = 3306
    username = "root"
    password = "password"
    database = ["mydb"]
    table = ["users", "orders"]
    startup.mode = "initial"
  }
}
sink {
  Kafka {
    bootstrap.servers = "kafka-host:9092"
    topic = "mysql_cdc"
    format = "canal_json"
    semantic = "EXACTLY_ONCE"
  }
}
```

### How Documentation Works

Documentation content lives in the **main codebase** (`apache/seatunnel` repo, `docs/` directory). The website repo fetches docs via `npm run sync` (or `tools/build-docs.js`) before building.

The sync process:
1. Creates `swap/` directory, clones `apache/seatunnel` codebase
2. Copies `docs/en` to website's `docs/` directory
3. Copies `docs/zh` to `i18n/zh-CN/` for Chinese translations
4. Copies `docs/images` to `static/image_en` and `static/image_zh`
5. Copies `docs/sidebars.js` to root level

### FAQ

**Q: BATCH vs STREAMING?**
A: BATCH = one-time execution (full migration); STREAMING = continuous (real-time sync, CDC)

**Q: Schema changes during CDC?**
A: `source { Mysql { schema_change_mode = "auto" } }`

**Q: Web UI?**
A: `git clone https://github.com/apache/seatunnel-web.git` -> build & run on port 8080

**Q: Max throughput?**
A: Typical 100K-1M records/second per executor, depends on hardware and data characteristics.
